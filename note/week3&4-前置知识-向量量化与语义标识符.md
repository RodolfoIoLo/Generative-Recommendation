## 1. 为什么要把向量变成离散码

`item_emb.npy` 里每个物品是一个 384 维实数向量。当前 T5 训练接口选择离散 token，因此需要先完成量化，有三个具体原因。

### 1.1 障碍一：语言模型的输入必须是 token

当前 T5 式模型的输入是一个**整数序列**（每个整数是词表下标），输出也是整数序列。内部 `nn.Embedding(vocab_size, d_model)` 使用整数查表得到向量。

现有训练接口没有直接接收 384 维物品向量的输入通道；词表也不存在“第 3.7 号 token”。理论上可以另行设计连续向量投影层，但那将成为另一种模型方案。

因此，后续 T5 式模型把语义 ID 当作词表符号时，**语义 ID 必须表示为整数或整数元组**。

### 1.2 障碍二：直接用一个整数当 ID 没有语义

这一步是最容易被跳过的。给每个物品编个号（0 到 3415）也是整数，为什么不行？

因为这样编出来的号**不携带任何语义信息**。物品 100 和物品 101 在编号上相邻，但它们可能一部是恐怖片、一部是儿童动画。模型要花大量数据去学「编号 100 和 101 其实毫无关系」这件事。

语义 ID 的设计目标是让**共享前缀的物品在文本空间中整体更相似**。例如，两部语义接近的电影可能共享 `(37,128,...)` 这样的前缀，生成模型便能在相同 token 和参数上共享统计信息；但具体电影对不保证一定共享前缀。

TIGER 论文 Abstract 将语义 ID 与未交互物品上的泛化改进联系起来。其机制动机是：前缀共享允许物品复用部分 token 与模型参数，从而为冷启动提供技术可能，而不是保证任意未见物品都能被正确生成。本项目当前划分的 strict-cold 目标数为 0，因此不能用现有主结果直接验证严格冷启动收益。

> 这条是**假设**，不是自动成立的。第 3–4 周的「任务 10 前缀语义一致性验证」就是在当前数据上实测这条假设。

### 1.3 障碍三：码长必须固定

语义 ID 按 TIGER 的冲突处理方式冻结为 4 位。这样 T5 每生成一个物品固定解码 4 个位置 token，再生成 EOS；序列长度与约束路径都容易统一。

如果长度可变，每步解码还要判断「结束了没有」，训练和推理都复杂得多。

## 2. 向量量化的最小定义

这一节只有 4 个概念，但后面所有内容都建立在它们之上。

### 2.1 码本（codebook）

**码本是一张表**，形状是 `K × d`：

- `K` = 表里有多少行，叫**码本大小**（codebook size / cardinality）
- `d` = 每行有多少个数，叫**码字维度**（也是量化空间的维度）
- 表的第 `k` 行记作 `e_k`，叫一个**码字**（codeword）

本项目设置为 `K = 256`、`d = 32`，所以每层码本是一个 `256 × 32` 矩阵。

在 RQ-VAE 中，码本是可训练参数；在 RQ-KMeans 中，对应的表由聚类中心直接确定。两种方案都用最近邻查表产生离散码，但码本的获得方式不同。

### 2.2 量化（quantization）

给定一个输入向量 `z ∈ R^d`，量化做的事是**查表找最近的一行**：

```
c = argmin_k ‖ z − e_k ‖²        ← 在所有 256 个码字里找欧氏距离最近的那个
z_q = e_c                        ← 用那个码字代替原来的向量
```

- `c` 是**离散码**（0 到 255 之间的整数），也是最终语义 ID 的**一位**
- `z_q` 是**量化后的向量**，它是码本里的某一行，不是任意向量

「最近邻查表」这个词就是这个意思：拿 `z` 去码本里逐行算距离，取最小的那一行。

### 2.3 量化误差

```
量化误差 = ‖ z − z_q ‖²
```

因为 `z_q` 被限制在 256 个点上，而 `z` 可以取任意值，所以误差一般不为 0。**码本越大、码字越贴合数据分布，误差越小**。

### 2.4 码本利用率

```
利用率 = (被使用到的码字数) / K
```

如果一个码本有 256 行，但 3416 个物品总共只用到其中 40 行，利用率就是 `40/256 = 15.6%`。**剩下 216 行是白占参数的，等于 K 实际上只有 40。**

极端情况叫**码本塌缩**（codebook collapse）：绝大部分物品挤在少数几个码字上，码本实际上退化成一个小得多的表。§6 专门讲这个。

### 2.5 一个具体的数：单层量化为什么不够

本项目共有 3416 个物品，并设置 `K = 256`。如果只做一层量化，就是**3416 个物品被分配到 256 个代表点**：

```
3416 / 256 ≈ 13.3     ← 平均每个码字要代表 13.3 个物品
```

这 13.3 个物品在语义 ID 的第 1 位上完全相同，**它们之间的差别全丢了**。

怎么办？两条路：

- 路 A：把 `K` 开大。想让 3416 个物品各有各的码，`K` 至少 3416，而且每个码字 32 维 → 码本参数 `3416 × 32 = 109,312`。还行，但物品数再涨就爆了。
- 路 B：**残差量化** —— 用多层，每层只负责「上一层没表达出来的那部分」。这就是 §4。

TIGER 选的是路 B。

## 3. VQ-VAE：三段结构与三项损失

### 3.1 名字先拆开

**VQ-VAE** = **V**ector **Q**uantized **V**ariational **A**uto**E**ncoder。

这个名字容易误导。它和普通 VAE 有两个实质区别：

- 普通 VAE 的隐变量是**连续**的高斯分布，用重参数化技巧采样；
- VQ-VAE 的隐变量是**离散**的（码本下标），没有采样，也没有 KL 散度项。

之所以还叫 VAE，是因为它沿用了「重建 + 先验」这套损失形式：把离散码的先验取成**均匀分布**之后，KL 项退化成一个常数，就只剩下面 §3.3 的那三项了。

**因此，可以把它理解为「自编码器 + 一个离散瓶颈」。**

### 3.2 三段结构

```
        x  (输入：物品的语义 embedding，D 维)
        │
   ┌────▼─────────────┐
   │  编码器 E         │   MLP：D → 512 → 256 → 128 → 32
   └────┬─────────────┘
        │  z_e  ∈ R^32       ← 连续向量
        │
   ┌────▼─────────────┐
   │  量化器 Q         │   c = argmin_k ‖z_e − e_k‖² ；z_q = e_c
   │  （码本 256×32）  │   c ∈ {0,...,255}
   └────┬─────────────┘
        │  z_q  ∈ R^32       ← 码本里的某一行
        │
   ┌────▼─────────────┐
   │  解码器 D         │   MLP：32 → 128 → 256 → 512 → D
   └────┬─────────────┘
        │
        x̂  (重建出的 embedding)
```

维度链 `512 → 256 → 128 → 32` 来自 TIGER Section 4 原文：

> *"The encoder has three intermediate layers of size 512, 256 and 128 with ReLU activation, with a final latent representation dimension of 32."*

**注意最后一跳是 32**。前面三个数（512/256/128）是隐藏层，**真正的量化维度是 32**，码本里每个码字也是 32 维。这是读论文时最容易看错的一处。

参数量的量级（`D = 384` 时，自己可以核）：

| 部分 | 参数量 |
|---|---|
| 编码器 MLP | 384×512 + 512×256 + 256×128 + 128×32 ≈ 364,544 |
| 解码器 MLP | 32×128 + 128×256 + 256×512 + 512×384 ≈ 364,544 |
| 码本（3 层） | 3 × 256 × 32 = 24,576 |
| **合计** | **约 0.75M** |

由此可见，当前 `D = 384` 的 RQ-VAE 只有约 75 万参数；模型规模远小于后续生成式推荐模型。

### 3.3 三项损失，各管一段

TIGER Section 3.1 原文：

> *"The RQ-VAE loss is defined as L(x) := L_recon + L_rqvae, where L_recon := ‖x − x̂‖², and*
> *L_rqvae := Σ_{d=0}^{m−1} { ‖sg[r_i] − e_{c_i}‖² + β‖r_i − sg[e_{c_i}]‖² }."*

β 的取值在 Section 4：*"When computing the total loss, we use β=0.25."*

三项拆开看：

| 项 | 公式 | 训练谁 | 在干什么 |
|---|---|---|---|
| 重建损失 | `‖x − x̂‖²` | 编码器 + 解码器 | 让解码器能从 `z_q` 还原出 `x`。这是主目标 |
| 码本损失 | `‖sg[z_e] − e_c‖²` | **只训练码本** | 把被选中的码字 `e_c` 拉向分配给它的 `z_e` |
| 承诺损失 | `β‖z_e − sg[e_c]‖²` | **只训练编码器** | 让编码器输出的 `z_e` 别乱跑，靠拢已有的码字 |

三项各管一段，靠 `sg`（stop-gradient）把梯度隔开。

### 3.4 stop-gradient 与直通估计器

这两个是 VQ-VAE 唯一真正需要动脑的地方。

**问题**：`c = argmin_k ‖z_e − e_k‖²` 这一步是**不可导的**。`argmin` 是一个「跳变」操作 —— `z_e` 挪一点点，`c` 可能从 37 跳到 38，也可能不动。没有导数，反向传播到这里就断了。

**做法**：假装量化不存在。前向传播照常 `z_q = e_c`；反向传播时，把 `z_q` 收到的梯度**直接复制**给 `z_e`。

```
前向：  z_q = e_c
反向：  ∂L/∂z_e  :=  ∂L/∂z_q        ← 直接搬过去，不管 argmin 那一步
```

这叫**直通估计器**（straight-through estimator，STE）。

**那 `e_c` 自己的梯度从哪来？** 直通估计器只解决了编码器那一侧。码本那一侧靠**码本损失**：`‖sg[z_e] − e_c‖²`。

**`sg` 是什么**：`sg[a]` 在前向传播时就是 `a`，反向传播时梯度为 0。所以：

- `‖sg[z_e] − e_c‖²` 里 `sg[z_e]` 是常数，只有 `e_c` 有梯度 → **只更新码本**
- `‖z_e − sg[e_c]‖²` 里 `sg[e_c]` 是常数，只有 `z_e` 有梯度 → **只更新编码器**

两个 `sg` 一左一右，就把「码本」和「编码器」这两个本该一起动的部分拆成两次独立的更新。

**为什么编码器那一项要乘 β = 0.25**：这一项是「约束项」，不是主目标。乘一个小系数是让编码器**愿意**靠拢码字，但不要为了靠拢而牺牲重建质量。β 太大会让 `z_e` 全挤在码字附近（重建变差），太小则编码器完全不理码本。

## 4. 残差量化（RQ）

### 4.1 「残差」是哪个减哪个

残差（residual）在这套里就是**减完剩下的那部分**：

```
r = z − z_q
```

`z` 是原向量，`z_q` 是它被量化后的码字，`r` 就是「量化没表达出来的部分」。

### 4.2 L 层怎么叠

残差量化做的事：**第一层量化原向量，第二层量化第一层的残差，第三层量化第二层的残差**，以此类推。

```
r_0 = z
c_1 = argmin_k ‖ r_0 − e^{(1)}_k ‖²        r_1 = r_0 − e^{(1)}_{c_1}
c_2 = argmin_k ‖ r_1 − e^{(2)}_k ‖²        r_2 = r_1 − e^{(2)}_{c_2}
c_3 = argmin_k ‖ r_2 − e^{(3)}_k ‖²        r_3 = r_2 − e^{(3)}_{c_3}
...
语义 ID = (c_1, c_2, c_3, ...)
重建   z ≈ e^{(1)}_{c_1} + e^{(2)}_{c_2} + e^{(3)}_{c_3} + ...
```

三个要点：

1. **每层有自己的码本**。`e^{(1)}` 和 `e^{(2)}` 是两个独立的 `256 × 32` 矩阵，不共享参数。所以第 1 层的码字 37 和第 2 层的码字 37 是两个完全不同的东西。
2. **层与层之间是串联的**。第 2 层必须在第 1 层算完之后才能算 —— 它要拿 `r_1` 当输入。
3. **重建是各层码字相加**，不是最后一层单独重建。

TIGER Section 4 原文：*"To quantize this representation, three levels of residual quantization is done. For each level, a codebook of cardinality 256 is maintained, where each vector in the codebook has a dimension of 32."*

### 4.3 为什么这样能省参数（关键的一节）

先算组合数。`L = 3`、`K = 256`：

```
K^L = 256³ = 16,777,216        ← 一千六百多万种不同的语义 ID
```

当前数据只有 3416 个物品，**代表点的数量远远够用。**

再看参数量：

| 方案 | 代表点数量 | 参数量 |
|---|---|---|
| 单层、K = 256 | 256 | 256 × 32 = **8,192** |
| 单层、K = 16,777,216（为了够用） | 16,777,216 | 16,777,216 × 32 ≈ **5.37 亿** |
| **三层残差、K = 256** | **16,777,216** | 3 × 256 × 32 = **24,576** |

**同样的表达能力，参数量差了 2 万倍。**

这就是残差量化的全部价值：**用「多层小码本的加和」代替「单层巨型码本」，把表达能力的增长从线性（K）变成指数（K^L），而参数只线性增长（L × K × d）。**

代价是：多算 L 次最近邻查表（推理变慢），以及层数越深越难训练（§6 的塌缩主要发生在深层）。

## 5. RQ-Kmeans：不训练的那条路

同样的残差量化结构，如果把「码本怎么学」换成**对当前残差做 k-means 聚类**，就得到 RQ-Kmeans。

```
X = item_emb                      (3416, D)
for l in 1..L:
    km_l = KMeans(n_clusters=256, n_init=10, random_state=42).fit(X)
    codes[:, l] = km_l.labels_                        ← 每个样本属于哪个簇
    X = X − km_l.cluster_centers_[codes[:, l]]        ← 减去簇心，得到残差
```

**簇心就是码字**，**簇编号就是离散码**。一层做完减去簇心，拿残差再做下一层。

### 5.1 和 RQ-VAE 的对照

| | RQ-Kmeans | RQ-VAE |
|---|---|---|
| 要不要训练 | **不用**，一次 `fit` 搞定 | 要，梯度下降若干 epoch |
| 码本怎么来 | 直接是聚类簇心 | 随机初始化后学出来 |
| 会不会塌缩 | 通常更稳定；本次三层均使用 256 个中心 | 会，是主要风险 |
| 重建质量 | 本次不作为 R² 主比较对象；第三层分配明显不均 | 本次最终 R²=0.623914 |
| 速度 | 当前数据规模下较快 | 需要预训练、初始化与联合训练 |
| 论文依据 | 任务要求允许的对照方案 | TIGER 的做法 |

### 5.2 为什么本次 RQ-KMeans 没有出现空码字

`KMeans(n_clusters=256)` 直接依据全体样本反复分配并更新聚类中心，比“只有被最近邻选中的码字才获得梯度”的随机初始化 VQ 训练更不容易形成永久死码字。本次实测三层均使用 `256/256` 个中心。

这不是对所有数据和初始化的数学保证；重复样本、退化数据或收敛问题仍可能导致有效簇不足。并且“被使用”不等于“使用均衡”：本次第三层困惑度只有 14.9，远低于 256。

因此不能仅凭 100% 利用率断言 RQ-KMeans 更好。最终 RQ-VAE 的三层困惑度达到 `219.3/232.0/241.1`，冲突率也显著更低，所以冻结 RQ-VAE 作为主语义 ID，RQ-KMeans 保留为对照。

## 6. 码本塌缩（阶段二最大的坑）

### 6.1 现象

训练完一看：256 个码字里只有 30 个被用到过，其余 226 个从头到尾没被任何样本选中。**码本退化成一个小得多的表。**

后果：语义 ID 的第 `l` 位实际只有 log₂(30) ≈ 5 bit 的信息量，而不是 log₂(256) = 8 bit。组合空间从 256³ 缩到 30³ ≈ 27000，虽然还是够用，但**码本参数白占了**，而且第 4 位消歧码会被大量触发（因为前 3 位撞码变多）。

### 6.2 成因（三条，按重要性排）

**① 死码字收不到梯度。**
码字的梯度只来自「分配给它的那些样本」。如果某个码字从第 1 个 batch 开始就没被任何样本选中，它永远收不到梯度，永远不更新，永远离数据很远 —— 形成自我强化的死循环。

**② 初始化不好会加速这个过程。**
码本随机初始化，如果某些码字一开始就落在数据分布之外，第一轮就不会被选中，然后进入 ①。

**③ 数据量小、K 大时更容易发生。**
当前数据包含 3416 个样本，每层有 256 个码字，**平均每个码字只有 13.3 个样本**。样本少意味着分配本身波动大：某次随机分配稍有偏差，某个码字少获得几个样本，就可能逐步滑向死亡。

这一点对当前数据尤其重要：TIGER 的物品集合更大，同样的 `K = 256` 能为每个码字提供更多样本。直接照搬超参数会提高 MovieLens 上的塌缩风险，最初完全坍塌的实测结果验证了这一判断。

### 6.3 四种修法

| # | 手段 | 做法 | 什么时候用 |
|---|---|---|---|
| 1 | **本项目最终方案** | 连续 AE 预训练 → 潜空间残差 K-Means 初始化 → RQ-VAE 联合训练 | 已解决完全坍塌 |
| 2 | 死码字重启 | 某码字长期无分配时，用当前潜向量重新初始化 | 仍存在局部死码字时 |
| 3 | EMA 更新码本 | 用分配到该码字的潜向量滑动平均更新中心 | 梯度版持续不稳定时 |
| 4 | 调整 `K` 或损失权重 | 降低码本大小，或重新搜索 commitment 权重 | 作为协议变更进行独立消融 |

修复策略必须同时检查重建质量、逐层利用率、困惑度与冲突率，不能只优化某一个数字。改变 `K` 会改变词表和实验协议，需要作为独立设置完整重跑。

## 7. 四个质量指标怎么算

### 7.1 码本利用率（逐层）

```
利用率_l = |{ c_l(i) : i = 1..3416 }| / K
```

就是「第 `l` 层出现过多少个不同的码字」除以 256。

**必须逐层报**。残差量化有个典型现象：第 1 层残差大、区分度高，利用率高；第 3 层残差已经接近噪声，大量物品落到少数几个码字上，利用率低。**只报平均会把这个现象抹掉**，而它恰恰是判断「L 该不该是 3」的依据。

### 7.2 困惑度（perplexity）

```
p_k = (被分配到第 k 个码字的物品数) / 3416
perplexity_l = exp( − Σ_{k=1..256} p_k · ln p_k )
```

困惑度是**有效码字数**的平滑版本：

- 256 个码字被完全均匀使用 → `perplexity = 256`
- 3416 个物品全挤在 1 个码字上 → `perplexity = 1`
- 200 个码字各拿 17 个、56 个码字拿 0 个 → `perplexity ≈ 200`

它比硬计数更早暴露问题：利用率可能还有 `200/256 = 78%`（看着还行），但困惑度已经掉到 100 以下（说明分配极不均匀）。

**两个都报，别只报一个。**

### 7.3 标识符冲突率

```
冲突率 = 1 − (不同的语义 ID 个数) / 3416
```

量化器首先产生核心三元组 `(c_1, c_2, c_3)`。不同物品得到同一个三元组，就叫**冲突**；本项目再为冲突组添加确定性的第 4 位消歧码 `c_4`，得到最终四元组 `(c_1, c_2, c_3, c_4)`。因此，消解前应统计核心三元组的冲突率，消解后再验证 3416 个最终标识符是否全部唯一。

**ML-1M 上的预期必须提前计算。** 对 `item_text.json` 的真实分布统计如下：

| 统计量 | 值 |
|---|---|
| 物品数 | 3,416 |
| 不同「年份 + 类型集合」组合数 | **1,479** |
| 不同类型集合数 | 299 |
| 年份范围 | 1919 – 2000（81 个不同年份） |
| 最大一组 | **66 部**（1999 年 + 仅 Drama） |
| 前 5 大组 | 1999/Drama 66、1998/Drama 65、1996/Drama 56、1997/Drama 52、1995/Drama 50 |

**如果编码器只学到「年份 + 类型」，3416 个物品只能落到 1479 个桶里，冲突率下界就是 `1 − 1479/3416 = 56.7%`。**

能不能突破这个下界，取决于 MiniLM 从**片名**里提取了多少可区分的语义。所以实测冲突率和 56.7% 的对照，本身就是对编码器质量的一次检验：

- 实测 ≈ 57% → 编码器基本只学到了年份和类型，片名信息没进去
- 实测明显低于 57% → 编码器确实从片名里学到了东西

保留这张统计表，可以清楚交代 `56.7%` 这一参照值的来源。

### 7.4 前缀语义一致性

**要验证的假设**：前缀相同的物品，语义应该相近。

**算法**：

```
1. 按第 1 位 c1 分组
2. 组内取所有物品对 (i, j)，算 cos(item_emb[i], item_emb[j])，求均值 μ_same
3. 从全部 3416 个物品里随机抽同样数量的物品对，求均值 μ_rand
4. 重复第 3 步 1000 次，得到 μ_rand 的分布 → 给 95% 区间
5. 对前缀 (c1, c2) 再做一遍
```

**预期**：`μ_same > μ_rand`，而且 `(c1,c2)` 的差距比 `(c1)` 更大（层级越深，同前缀的物品应该越相似）。

**如果第 3 层的 `μ_same` 反而掉下来了**，说明第 3 层已经量化到噪声上去了 —— 和 §7.1 里「第 3 层利用率低」的现象互相印证。两个指标一起看，能定位到「L 该不该是 3」这个问题上。

除统计量外，还应进行人工抽样：抽取 10 组同前缀物品并列出真实片名，同时至少保留 2 组同前缀但语义明显不同的反例。正例与反例均属于有效实验结果，有助于如实界定语义 ID 的能力边界。

## 8. TIGER 的真实数字（全部标出处）

以下配置均回到 arXiv:2305.05065v2 原文核实，也是后续构建 T5 生成式推荐模型的重要参考。

### 8.1 RQ-VAE 结构（Section 4 "RQ-VAE Implementation Details"）

| 项 | 值 |
|---|---|
| 编码器隐藏层 | 512, 256, 128（ReLU） |
| **潜表示维度** | **32** |
| 残差量化层数 | 3 |
| 每层码本大小 K | 256 |
| 码本向量维度 | 32 |

> 原文：*"The encoder has three intermediate layers of size 512, 256 and 128 with ReLU activation, with a final latent representation dimension of 32."*
> 原文：*"To quantize this representation, three levels of residual quantization is done. For each level, a codebook of cardinality 256 is maintained, where each vector in the codebook has a dimension of 32."*

### 8.2 损失函数（Section 3.1 "Semantic ID Generation"）

```
L(x) = L_recon + L_rqvae

L_recon = ‖ x − x̂ ‖²

L_rqvae = Σ_{d=0}^{m−1} { ‖ sg[r_i] − e_{c_i} ‖²  +  β · ‖ r_i − sg[e_{c_i}] ‖² }

β = 0.25          （Section 4: "When computing the total loss, we use β=0.25."）
sg = stop-gradient
```

> 原文里 `m` 就是量化层数（= 3），`r_i` 是第 `i` 层的残差。

### 8.3 冲突处理（Section 3.1 "Handling Collisions"）

> 原文：*"To remove the collisions, we append an extra token at the end of the ordered semantic codes to make them unique. For example, if two items share the Semantic ID (12,24,52), we append additional tokens to differentiate them, representing the two items as (12,24,52,0) and (12,24,52,1). To detect collisions, we maintain a lookup table that maps Semantic IDs to corresponding items. Note that collision detection and fixing is done only once after the RQ-VAE model is trained."*

Section 4 补充：*"if there are no collisions, we still assign 0 as the fourth codeword."*

三条要点：

1. **语义 ID 长度是 4，但量化层数只有 3**。第 4 位不是量化出来的，是**消歧用的序号**。
2. **没有冲突也补 0**。所以每个物品都是 4 位，长度统一。
3. **冲突检测只做一次**，在 RQ-VAE 训练完之后。不要放在训练循环里。

### 8.4 词表大小（Section 4 "Sequence-to-Sequence Model Implementation Details"）

> 原文：*"the vocabulary contains 1024 (256×4) tokens to represent items in the corpus. In addition to the semantic codewords for items, we add user-specific tokens to the vocabulary. To keep the vocabulary size limited, we only add 2000 tokens for user IDs."*

| 部分 | 大小 |
|---|---|
| 物品 token | **1024 = 256 × 4** |
| 用户 token | 2000 |
| 合计 | 3024 |

**`256 × 4` 里的 4 是「码字位置数」**：3 个量化位 + 1 个消歧位。每一层（包括消歧那一层）都占一个完整的 256 大小的码本位。

**层与层之间不共享 token。** 第 1 层的码字 37 和第 2 层的码字 37 是两个不同的词，在词表里占两个不同的下标。所以是 `4 × 256`，不是 `256 + 4`。

## 9. 术语速查表

| 术语 | 英文 | 一句话定义 |
|---|---|---|
| 向量量化 | Vector Quantization | 把连续向量映射成离散码的过程 |
| 码本 | codebook | `K × d` 的可训练参数表，每行是一个码字 |
| 码字 | codeword | 码本的一行，一个 `d` 维向量 |
| 码本大小 | codebook size / cardinality | `K`，码本有多少行 |
| 离散码 | code | `argmin` 得到的下标，`0..K−1` 的整数 |
| 量化误差 | quantization error | `‖z − z_q‖²` |
| 最近邻查表 | nearest-neighbor lookup | `c = argmin_k ‖z − e_k‖²` |
| VQ-VAE | — | 编码器 + 离散瓶颈 + 解码器的自编码器 |
| 直通估计器 | straight-through estimator | 前向照常，反向把 `z_q` 的梯度直接搬给 `z_e` |
| stop-gradient | `sg[·]` | 前向等于原值，反向梯度为 0 |
| 承诺损失 | commitment loss | `β‖z_e − sg[e_c]‖²`，只训练编码器 |
| 残差 | residual | `r = z − z_q`，量化没表达出来的部分 |
| 残差量化 | Residual Quantization (RQ) | 第 `l` 层量化第 `l−1` 层的残差 |
| 码本塌缩 | codebook collapse | 只有少数码字被使用，其余闲置 |
| 死码字 | dead codeword | 从未被任何样本选中的码字 |
| 码本利用率 | codebook utilization | 被用到的码字数 / `K` |
| 困惑度 | perplexity | `exp(−Σ p_k ln p_k)`，有效码字数的平滑版 |
| 语义标识符 | Semantic ID | 物品的 `(c_1, ..., c_L)` 码元组 |
| 冲突 | collision | 不同物品得到同一个语义 ID |
| 消歧码 | deduplication code | 语义 ID 的最后一位，仅用于区分撞码物品 |
| RQ-Kmeans | — | 用 k-means 簇心当码字的残差量化，不用训练 |
| RQ-VAE | — | 用 VQ-VAE 学码本的残差量化，TIGER 的做法 |
