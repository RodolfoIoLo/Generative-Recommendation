# 🧭 从“看过什么”到“推荐什么”

问题只有一个：已知一个人的观看历史，预测下一部电影。这个项目把电影变成一串编号，再训练模型生成编号。先看下面的链路，不必先记模型名字。

## 1. 先整理观看记录

原始记录包含用户、电影和时间。按时间排好后，每人的最后一部留作测试，倒数第二部留作验证，其余用于训练。**训练集负责学习，验证集负责选方案，测试集负责最终比较。**

模型学习的是“前面看过这些电影，下一部是什么”。一条长序列可以截出很多这样的训练样本。真实数据规模和文件去向见[Week 1全景图](workflow-atlas.md#week-1)。

## 2. 用数字描述一部电影

电影标题和类型先输入现成的文本编码器MiniLM，得到384个数字。这叫**向量**；相近的向量表示文本含义相近。每行对应一部电影，所有行保存在`item_emb.npy`中；`.npy`只是NumPy数组的文件格式。

Week 7还从**训练集**观看行为中提取64维协同向量。“协同”表示哪些电影常被同一批用户观看；它与题材相似并不完全一样。将两类向量分别归一化、加权拼接，再整体归一化，得到448维输入。

四个对照只改变协同权重：Text为0，Fixed为1，Adaptive按训练频次分配，Fixed-Match用常数匹配Adaptive的平均协同强度。这里的Text仍是448维，末64维为0，保证输入维数一致。

## 3. 把向量压缩成语义ID

**码本**可以理解为一组可学习的代表向量。RQ-VAE先把输入压缩到32维，再从第一层码本选最近的代表；用剩下的误差去选第二层，再选第三层。记录每次选中的位置，就得到三段编号。

量化器先训练连续自编码器，使压缩后的向量能还原输入；再用逐层K-Means的聚类中心初始化码本，最后联合训练编码器、码本和解码器。这一初始化修复了最初“所有电影都选同一个码字”的坍缩。

如果三段编号仍重复，就追加组内序号作为第四段，保证每部电影能唯一查回。第四段负责消歧，不是第四层语义码本。正式ID、重建质量与冲突统计见[Week 3–4结果](../results/week3-4-semantic-id/README.md)。

## 4. 把编号交给生成模型

模型把每一段编号当成一个**Token**，即一个可读写的符号。四个位置各有256种取值，加上填充、开始、结束三个符号，词表共有`4×256+3=1027`个Token。

例如，虚构ID`(37,128,5,0)`按位置映射为`[40,387,520,771]`，规则为`3+位置×256+码值`，位置从0开始。相同码值在不同位置对应不同Token。

模型最多读取最近20部电影，也就是80个ID Token，再加结束符。Encoder先理解历史，Decoder逐位预测下一部电影的4个Token和结束符。这个小型T5式模型从随机参数开始训练；文本编码器的现成权重不作为它的初始化。

## 5. 它怎样学习，怎样推荐？

训练时提供真实下一部电影的编号：预测第二位时已经知道真实第一位，以此类推。这叫**teacher forcing**。把每一位预测错的程度汇总成损失，再反向传播更新模型参数；推荐损失不会反向更新已经冻结的语义ID量化器。

推荐时没有真实答案，模型只能接着自己生成的前缀写下去。**Beam Search**每一步保留若干条高分候选前缀；**Trie**是一棵合法编号前缀树，用来阻止不存在的电影编号，并排除完整历史里看过的电影。完整编号查回电影，形成Top-10列表。

这里“全目录候选”表示没有抽取少量负例；Beam20仍是近似检索，并没有逐一精确计算所有电影的概率。[训练内部详图](generative-training-diagram.md)展开了张量、梯度和解码过程。

## 6. 怎样知道推荐得好不好？

每名测试用户有一部真实的“下一部电影”。Recall@10看它是否出现在前十；NDCG@10还看排得是否靠前。三个随机种子分别训练，再报告均值和标准差，避免只展示一次幸运结果。

最终Fixed相对受控Text的NDCG@10提高约17.0%，与GRU4Rec总体接近，长尾组仍较弱。完整对比见[最终报告](../results/week7-improvement/06-evaluation/main_results.md)；想把概念对应到文件，可以沿[五张全景图](workflow-atlas.md)逐步阅读。
