# 码本质量分析报告

> MovieLens 1M，3,416 个物品；文本编码器 `all-MiniLM-L6-v2`；输入为 384 维 L2 单位向量。正式接口采用 RQ-VAE，`L=3`、`K=256`、latent 32、seed 42。

## 结论

RQ-VAE 经“连续 AE 预训练 → 潜空间残差 K-Means 初始化 → 联合训练”后解决了完全码本坍塌。正式 checkpoint 的重建 `R²=0.623914`，三层利用数为 `256/253/253`，困惑度为 `219.3/232.0/241.1`；消歧前仅 5 组二元冲突，追加确定性组内序号后 3,416 个物品全部唯一。前缀一致性验证显示，共享 1/2/3 位前缀的物品均比随机物品对更相似。因此冻结三层 RQ-VAE 前缀加一位消歧码，四层纯语义方案保留为后续消融。

## 1. 输入与协议

| 项目 | 设置 |
|---|---|
| 物品文本 | `title (year) \| genres` |
| embedding | `(3416,384)`，`float32`，逐行 L2 范数约为 1 |
| embedding SHA-256 | `162d6d2a9fb89e6b9e096d97a79a46338d83507ad5cbc07581a730d43e2b77a4` |
| RQ-VAE | `384→512→256→128→32` 编码器，镜像解码器，三层 `256×32` 码本 |
| 训练 | AE 200 epochs；残差 K-Means 初始化；联合训练 2,000 epochs，Adam，`lr=1e-4`，`β=0.25` |
| checkpoint 选择 | 三层利用率均不低于 90%，再按重建 R² 选优 |
| 冲突消解 | 对相同三位前缀按连续物品 ID 追加组内序号 `0,1,...` |

## 2. 坍塌诊断与修复

随机小范围初始化的 smoke test 出现完全坍塌：三层均只使用 `1/256` 个码字，3,416 个物品只有 1 个前缀，最佳 `R²=-0.0016`。此时离散瓶颈比始终预测均值还差，不能继续正式训练。

修复流程先训练连续 AE，使 32 维潜空间保留可重建结构（最佳 `R²=0.6707`）；再对全部潜向量逐层做残差 K-Means，将质心写入码本；最后联合优化重建、码本和承诺损失。这样码字从真实数据分布附近开始训练，避免所有样本在初始阶段集中到同一位置。

## 3. 正式方法对比

| 方法 | 重建 R² | mean-MSE | 利用数 | 困惑度 | 消歧前唯一数 | 冲突率 | 最大冲突组 | 消歧后唯一数 |
|---|---:|---:|---|---|---:|---:|---:|---:|
| RQ-KMeans | 0.595971¹ | 0.00075384 | 256 / 256 / 256 | 201.0 / 97.4 / 14.9 | 3,321 | 2.78% | 3 | 3,416 |
| **RQ-VAE** | **0.623914** | **0.00070171** | **256 / 253 / 253** | **219.3 / 232.0 / 241.1** | **3,411** | **0.15%** | **2** | **3,416** |

¹ 原 RQ-KMeans 训练日志没有输出 R²；这里以三层聚类中心之和作为重建向量，从正式码本只读复算。该补充值未参与原实验的模型选择。

RQ-KMeans 虽然每层使用了全部码字，但第三层困惑度只有 14.9，说明分配极不均衡；“使用过”不等于“使用均衡”。RQ-VAE 三层困惑度均超过 219，且冲突率降低约 18 倍，整体码本质量更好。

## 4. `(L,K)` 网格

| 方法 | L | K | R² | 利用数 | 消歧前冲突率 |
|---|---:|---:|---:|---|---:|
| RQ-KMeans | 2 | 64 | — | 64 / 64 | 47.72% |
| RQ-KMeans | 2 | 256 | — | 256 / 256 | 16.16% |
| RQ-KMeans | 3 | 64 | — | 64 / 64 / 64 | 5.09% |
| RQ-KMeans | 3 | 256 | — | 256 / 256 / 256 | 2.78% |
| RQ-VAE | 2 | 64 | 0.4835 | 64 / 64 | 39.20% |
| RQ-VAE | 2 | 256 | 0.5749 | 256 / 254 | 4.39% |
| RQ-VAE | 3 | 64 | 0.5354 | 64 / 64 / 64 | 2.43% |
| **RQ-VAE** | **3** | **256** | **0.6245** | **256 / 255 / 250** | **0.18%** |

增加 `L` 或 `K` 均能降低碰撞，但 RQ-VAE 在相同容量下明显优于 RQ-KMeans。额外的四层纯 RQ-VAE 达到 `R²=0.6566`、利用数 `256/253/253/247`，不追加消歧码也得到 3,416 个唯一 ID；由于该网格运行没有保存正式可复验 checkpoint，暂不替换主接口。

## 5. 前缀语义一致性

| 前缀深度 | 同前缀平均余弦 | 随机平均余弦 | 差值 | pair-bootstrap 95% CI | 同前缀对数 |
|---|---:|---:|---:|---:|---:|
| 1 | 0.5289 | 0.2832 | +0.2456 | `[0.2436,0.2476]` | 29,251 |
| 2 | 0.7116 | 0.2832 | +0.4284 | `[0.4079,0.4498]` | 195 |
| 3 | 0.8089 | 0.2832 | +0.5257 | `[0.4101,0.6314]` | 5 |

三个深度的差值区间均完全大于 0，说明在当前 MovieLens embedding 上，共享前缀稳定对应更高文本相似度。第三层只有 5 个成对样本，区间较宽，不能据此作总体显著性或因果推断。人工检查记录了 10 组正例和 2 组反例，详见 [`prefix_consistency.md`](../04-prefix-validation/prefix_consistency.md)。

## 6. 冻结接口

最终物品标识为 `(c₁,c₂,c₃,d)`：前三位来自 RQ-VAE，`d` 是冲突组内序号。第四位不参与码本利用率和困惑度分析，但在生成模型中占独立的 256-token 位置，因此物品 token 数为 `4×256=1024`，加入 `<pad>/<bos>/<eos>` 后总词表为 1,027。

`../05-frozen-interface/` 中包含语义 ID、三个语义序列 split、词表和元数据。独立复验确认：3,416 个四元组全部唯一；码值均在 `0..255`；三个 split 各 6,040 行且逐项转换正确；`meta.json` 中 embedding、checkpoint、语义 ID 和原始 split 的 SHA-256 均可重算一致。

## 7. 局限性

- 文本仅包含标题、年份和类型，前缀可能受片名词面或年份影响，不等同于人工电影分类。
- pair-bootstrap 以物品对为描述单位，共享物品会造成相关性，因此不外推为 MovieLens 之外的严格显著性结论。
- 第四位是确定性消歧码而非语义码；四层纯语义方案需要保存并复验正式 checkpoint 后才能公平替换。
- 本阶段只验证语义结构和接口正确性；后续生成实验未显示相对序列基线的指标优势，详见 [`Week 5–6 主实验`](../../week5-6-generative/06-reports/main_results.md)。
